# AE-CAI 改訂の検証実験 —— 現状（2026-10-10）

HTL 特集号（major revision）の査読対応で行った追加実験の現状を、1 枚にまとめる。
数値はすべて表から写した（表は `python3 -m aecai_rev.summary` などが自動で書く）。
同じ実験は workbench（surgical-3d-workbench）の `aecai_revision_experiment/` にもあり、
こちらで出した表とバイト一致する。対照実験（再実行 27 窓）と生存率の GT 検算は
workbench にだけあり、このリポジトリにはまだ反映していない。各数値の形式は「平均 [窓単位ブートストラップ 95 % CI]」、差は
「a − b」で、★ は窓単位・動画単位の両方の CI が 0 をまたがないことを表す。

---

## 1. 結論の要約

1. **原稿の Table 1 は完全に再現できた。** 凍結トラックをタグの評価器で採点し直すと、
   81 個の JSON がバイト一致する。
2. **「normal は RGB より F1 が高い」は統計的に支持されない。** 原稿と同じ 27 窓でも
   CI は 0 をまたぎ、深度推定（DA3）をこの環境でやり直すだけで差はほぼ消える。
   86 窓では符号が逆になる（いずれも有意ではない）。
3. **「normal のノードは時間方向に安定」も支持されない。** normal の生存率が RGB より
   高いのは、正しく残る割合が多いからではなく、別のクラスへずれたまま残る割合が
   多いためだった。RGB の領域数を normal にそろえると、生存率は RGB が同じか上。
4. **normal は depth よりははっきり良い**（F1・oracle mIoU・命名可能率）。
5. **normal の結果は DA3 の出力の揺れに敏感。** 同じ入力でも、27 窓中 11 窓で深度の
   倍率と焦点距離が変わり、normal の F1 だけが動く（RGB は不変）。

## 3. 主要な結果

### 3.1 F1 と oracle mIoU（pps 24、原稿と同じ 300 px）

| | 凍結 27 窓 | 再実行 27 窓 | 86 窓 |
|---|---|---|---|
| F1@.5 RGB | 0.562 | 0.562 | 0.557 |
| F1@.5 depth | 0.480 | 0.495 | 0.488 |
| F1@.5 normal | 0.589 | 0.567 | 0.529 |
| **normal − RGB** | +0.027 [−0.022, +0.075] | +0.004 [−0.050, +0.056] | −0.028 [−0.066, +0.010] |
| normal − depth | +0.109 ★ | +0.072 ★ | +0.041（動画 CI は 0 をまたぐ） |
| oracle mIoU normal − RGB | −0.111 ★ | −0.124 ★ | −0.173 ★ |

面積比 0.001 で数えても結論は同じ（normal − RGB は +0.029 / +0.005 / −0.025、
いずれも CI が 0 をまたぐ）。

### 3.2 粒度（pps）をそろえると

- pps を 8〜32 に振っても、領域数はあまり動かない（seed の 400 px 下限などのため）。
  RGB の領域数を GT インスタンス数（約 10）まで下げるには pps 6 が要った。
- 領域数がそろう条件（RGB は pps 6、normal は pps 24）での F1@.5:
  27 窓は RGB 0.587 / normal 0.580、86 窓は RGB 0.590 / normal 0.522
  （この組み合わせどうしの検定はしていない）。
- 同じ pps どうしの normal − RGB は、86 窓では pps 6・8 で −0.078 ★。
  27 窓ではどの pps でも差がない。

### 3.3 GT インスタンス単位でマージした後の F1@.5（pps 24）

| | 凍結 27 窓 | 再実行 27 窓 | 86 窓 |
|---|---|---|---|
| RGB | 0.552 → 0.804 | 0.552 → 0.804 | 0.547 → 0.791 |
| normal | 0.580 → 0.714 | 0.556 → 0.691 | 0.522 → 0.623 |
| マージ後の normal − RGB | −0.091 ★ | −0.114 ★ | −0.167 ★ |

RGB の領域は断片化しているが、断片を正しくまとめれば RGB の方が GT によく合う。
oracle mIoU はマージでほとんど変わらない（−0.001）。

### 3.4 時間方向

**生存率（seed で作った領域のマスクが、その後のフレームで残っている割合）**:
normal は RGB より +0.04 前後高い（3 母集団とも ★）。

**GT で検算すると**（注釈フレームごとに、残ったマスクが元のクラスの上にあるかを見る。
86 窓、pps 24）:

| | normal | RGB | RGB（pps 6、領域数をそろえた） |
|---|---|---|---|
| 正しく残っている | 79 % | 80 % | 86 % |
| 残っているが別のクラスにずれた | **12 %** | 6 % | 6 % |
| 元の物体は写っているのに見失った | 8 % | **12 %** | 6 % |
| 残っているマスクのうちずれているもの | 13 % | 7 % | 7 % |
| 前方の生存率 | 0.907 | 0.867 | 0.926 |

- 正しく残る割合は normal と RGB で同じ。normal は「見失い」が少ない分「ずれ」が多い
  （ずれ: normal − RGB = +0.057 ★、27 窓でも +0.038 ★）。
- RGB の領域数をそろえると、RGB は生存率も正しく残る割合も normal 以上
  （normal − RGB pps 6 の「元の物体が写っているときに正しく残る割合」:
  86 窓 −0.071 ★、27 窓 −0.050 ★）。
- ここでの「ずれ」は意味クラス基準。normal はクラスをまたぐ面を 1 領域にまとめる
  ことがあるので、その分も「ずれ」に数えている可能性はある（未検証）。

**ID switch 率**: 0.04〜0.06 で、モダリティ間に差なし。ただし大半は GT 側の連結成分の
分裂・合体による見かけのもので、クラス単位では 0.003〜0.008。

### 3.5 器具-組織の併合と命名可能率（pps 24）

| | 凍結 27 窓 | 再実行 27 窓 | 86 窓 |
|---|---|---|---|
| 併合した領域の割合 normal / RGB | 0.6 % / 0 % | 1.2 % / 0 % | 2.7 % / 0 % |
| 併合が起きたフレーム normal | 5.9 % | 10.5 % | 14.5 % |
| 1 クラスに名前が付く割合 normal / RGB / depth | 0.83 / 0.91 / 0.75 | 0.83 / 0.91 / 0.75 | 0.79 / 0.89 / 0.75 |

（併合は既存 overlay の閾値、すなわち包含 0.8 または IoU 0.3 で数えた。）

## 4. 原稿の記述と食い違う点

1. **フレーム間隔**: 原稿は「0.6 秒間隔・17.4 秒」とするが、27 窓のうち 17 窓は
   CholecSeg8k が約 30 fps で番号を振った動画で、実際は 0.5 秒間隔・14.5 秒。
2. **フレーム順**: 11 窓では、注釈の無いフレームが 1〜3 秒ずれた位置から取られ、
   時間順が乱れている（抽出器の既知の問題）。項目 4 は順序の正しい 16 窓だけでも出した。
   86 窓は直した抽出器で作ったので乱れは無い。
3. **トラッカー**: 実装は SAM 3 のトラッカー（原稿は SAM 2 を引用。既知・意図的）。
4. **深度の再現性**: DA3 は同じ入力でも環境が変わると 11/27 窓で倍率・焦点距離ごと
   変わる（workbench の `aecai_revision_experiment/results/legacy27_env/compare_depth.csv`）。原稿の normal の数値は、
   この揺れの 1 回分を測ったものになっている。
5. **Fig. 6**（object 14/15 の時系列グラフ）の元データがこのマシンに無い。名前付き
   イベントの読み出しは別の窓で例を出した（`results/aecai_rev/06_naming/fig6_named_events.txt`）。

## 5. 決めてほしいこと

1. **原稿の主張をどうするか。** 今の数字のまま書けるのは「normal は depth より良い」
   と「normal は F1 で RGB と同程度、領域数は少ない」まで。「RGB に勝つ」「時間方向に
   安定」は支持されない。
2. **本文に載せる母集団。** 選択バイアスの指摘に答えるなら 86 窓。ただし 86 窓の深度は
   この環境で作ったもので、凍結 27 窓とは条件が完全には同じでない。
3. **仮に決めた点**（`results/aecai_rev/00_inventory.md` §8）: 「clip」を CholecSeg8k の 80 枚
   フォルダと解釈（86 窓。連続フォルダのまとまりなら 41 窓）、stride は CholecSeg8k の
   番号で数える、pps 4・6・48 を追加、判定は動画単位の CI。
4. **Fig. 6 の元データ**（ローカル PC の `temporal_graph__sam3d.json` と `pc_vis/`）を
   もらえれば、Fig. 6 の窓で名前付きイベントを出し直せる。
